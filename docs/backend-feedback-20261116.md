# 백엔드 답변 반영 기록

2026-11-16 회신과 최신 Notion 명세를 기준으로 콘솔에 반영했습니다. 코드 저장소는 `nuridot/adminPage`입니다.

## 콘솔 반영

- 분석 기간을 월/날짜로 선택하고 URL에 보존합니다. 기관 조건은 revenue, collections, order-funnel, usage, credit-low, ai-quality, attempt-success에만 전송합니다. 쪽 유형은 AI 두 API에만 전송합니다. 데이터셋은 기관·유형 조건을 보내지 않습니다. 서버가 실제 적용한 기간과 `basis.filters`를 표시합니다.
- 부족 잔액은 현재 기관 기준이며 `filters`를 별도로 표시합니다. 판정 대상 0개와 부족 기관 0개를 구분합니다. 쪽 유형 필터에서 처리 시간이 null이면 “유형별로는 볼 수 없음”을 표시합니다. 유형 없음(null)과 판정 불가(UNSPECIFIED) 행을 합산하지 않습니다.
- 메일 첨부 추가·삭제·다운로드와 확정 스냅샷을 연결했습니다. 확정 요청의 `attachmentIds`는 화면에서 확인한 첨부 목록과 일치합니다. 첨부 변경 후 서버의 DRAFT 상태를 다시 읽어 재확인 없이 발송하지 못하게 합니다. 파일당 10MB·총 17MB·10개, 빈 파일·차단 확장자를 검사합니다. 업로드 실패 결과가 불확실하면 자동 재전송하지 않습니다.
- 기존 MFA 등록·인증·복구 코드·중요 작업 재인증 흐름을 검증하고 콘솔 접근 불가·로그인 잠금 안내를 구분했습니다. 임시 토큰은 세션으로 저장하지 않습니다.
- 크레딧 관문을 유지한다는 답변에 맞춰 안내를 정정했습니다. 실행 관문 전환은 추가 개발 요구에서 제외합니다.
- 청구·입금·배분·환불은 수동 수금 기록입니다. PG 결제 연동을 뜻하지 않습니다. 서명본 업로드와 외부 세금계산서 발행 기록·취소를 유지합니다.

## Sentry

- 조직 `nuridot`, US 리전, 콘솔 전용 프로젝트 `nuridot-console` (4512442007617536). 서버 프로젝트 DSN을 공유하지 않습니다.
- GitHub Actions 변수 `VITE_SENTRY_DSN`에서 공개 DSN을 주입합니다. 운영 `prod`, 로컬 `local`, 운영 release는 배포 커밋 전체 SHA입니다. 예시 모드는 전송하지 않습니다.
- 오류 종류, 정적 번들 파일 위치·행·열, release와 환경만 허용합니다. 사용자 값은 토큰의 sub가 UUID인 경우에만 ID로 사용하며 로그인명으로 대체하지 않습니다.
- 오류 메시지 원문, 메일·점역 본문, 문서 파일명, 토큰, 요청 URL/본문/헤더, breadcrumbs, 임의 context·extra는 이벤트에서 제거합니다. 프로젝트에서 IP 저장을 차단합니다. 소스 자동 수집, 세션 리플레이, tracing, 프로파일링, 로그·메트릭 전송을 사용하지 않습니다.
- 로컬 검증 페이지에서 테스트 오류를 전송하고 `NURIDOT-CONSOLE-1` 수신을 확인했습니다. SDK의 `infer_ip: never`를 보존해 IP/위치 추론을 차단하고, 프로젝트에도 위치 필드 마스킹을 추가했습니다. 이 검증 페이지는 운영 빌드나 저장소에 포함하지 않습니다.

## 앱 이벤트: 콘솔과 별도로 필요한 작업

서버의 `job_created`, `conversion_result`, `credit_captured`, `login_result`를 콘솔에서 중복 전송하지 않습니다. 데스크톱 앱의 열기·저장·내보내기·완료·교정·활동 이벤트는 Windows 편집기 `nuridot/Semojum`에서 발생합니다. 11/17에 `/api/events` 계약이 반영됐고, 11/19 콘솔은 [새 집계 API 5개](app-events-20261119.md)를 연결했습니다. 아래 표는 11/16 회신 당시 논의입니다.

회신에서 언급한 `app-events-draft-20261116.md` 원문은 이번 첨부에 없습니다. 앱 저장소와 함께 다음 내용을 확정해야 합니다.

| 백엔드 확인 요청 | 현재 정리                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| 완료 동작        | 자동 저장·내보내기를 작업 완료로 추정하지 않음. 앱의 실제 완료 버튼/상태 전이 확인 필요           |
| 오류 코드        | 앱의 파일 열기·저장·내보내기 오류 코드 목록과 사용자 취소 구분 필요                               |
| 작업 회차        | 다시 열기·재교정 시 동일 작업과 새 회차를 구별할 workRevisionId 생성/종료 규칙 필요               |
| 내보내기 형식    | 앱에서 실제 지원하는 형식의 enum 필요. 확장자나 제품 명세를 추측하지 않음                         |
| 전송 경로        | 인증된 서버 중계를 권장. 이벤트 UUID로 중복 제거, 최대 100개 배치, 조직·계정은 서버 인증에서 결정 |

확정된 이벤트 이름은 document_open_result, save_result, export_result, job_completed, ai_revision_summary, activity_state_changed입니다. 전체 수집 스위치는 서버 환경 변수 APP_EVENTS_ENABLED로 관리하며, 콘솔 지표 연결과 수집 활성화는 별도입니다.

개발 DB는 분리되어 있으나 별도 개발 API 서버는 없다는 답변을 반영했습니다. 운영 데이터를 대상으로 시험용 계약·입금·메일을 만들지 않았습니다. 실제 운영 MFA 및 쓰기 작업은 콘솔용 인증과 시험 대상이 있어야 통합 검증할 수 있습니다.
