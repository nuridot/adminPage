## 계산과 운영 규칙

- 금액: 계약 MRR은 공급가, 주문·청구 수금은 부가세 포함. 주문 입금과 청구 입금을 합산하지 않습니다. MRR은 월말 스냅샷이며 기간 합계를 만들지 않습니다.
- 비율: 분자/분모를 함께 보여주고 분모 0은 `—`로 표시합니다. AI 시도 성공률과 쪽 결과 상태를 구분합니다. 교정률을 정확도로 부르지 않습니다.
- 데이터셋: 단위별로 구분합니다. 감소 정정으로 생긴 음수 증분을 보존합니다.
- 인증: 비밀번호 단계의 임시 MFA 토큰은 메모리에만 유지합니다. 인증 앱 등록 QR은 브라우저 안에서 생성하며 외부 QR 서비스에 보내지 않습니다. 복구 코드는 등록 응답에서 한 번 표시한 뒤 보관 확인을 받습니다.
- 중요한 변경은 입력→대상·내용 확인→서버 요청 순서입니다. AUTH4013이면 TOTP 재인증 후 원래 본문과 동일한 멱등 키로 한 번 재요청합니다. 취소하면 변경하지 않습니다.
- 네트워크 오류·5xx는 결과가 불확실할 수 있습니다. 멱등 작업만 같은 요청 키로 재확인할 수 있고, 그 외 작업은 재전송을 잠급니다. 모달을 닫거나 새로고침한 뒤에는 먼저 상세/원장을 확인해야 합니다.
- 메일은 저장본과 같은 수신자·참조·숨은 참조·제목·본문·첨부 ID 목록을 확인합니다. 첨부 추가/삭제 후에는 재확인이 필요합니다. `SEND_UNCERTAIN`/`SEND_REQUESTED`는 발송 재시도가 아닌 결과 조회를 제공합니다. HTTP 200이어도 `SEND_FAILED`를 성공으로 표시하지 않습니다. `PROVIDER_ACCEPTED`는 수신함 도착을 보장하지 않습니다.
- 메일 HTML은 실행·삽입하지 않고 글 본문만 표시합니다. 수신 첨부는 서버가 발급한 HTTPS URL로 엽니다.
- 예시 모드의 새 백오피스 기능은 조회 전용입니다. 변경 성공·실제 발송·다운로드를 흉내 내지 않습니다.

## 앱 이벤트 지표 및 별도 운영 연동

| 항목                                       | 현재 처리                                    | 서버·운영 후속 작업                       |
| ------------------------------------------ | -------------------------------------------- | ----------------------------------------- |
| 열기→변환→저장→완료 작업 퍼널·실패 후 복구 | work-funnel / app-reliability 연결             | 서버 수집 설정에 따라 실제 기록 표시     |
| 기관 유지 코호트·사용자 활동 시간          | org-retention / activity-time 연결             | 부분 활동 시간과 미완료 주를 구분        |
| 비교 관측률·순 편집량                      | revision-rate 연결, AI 원문과 엔진 점자 분리   | 완료 저장본과 일치하는 요약 사용          |
| 앱 버전별 지표 필터                        | 새 앱 이벤트 API 5개에 appVersion 전달         | 기존 서버 지표에는 버전 필터 미적용       |
| 전자서명·자동 세금계산서 발행              | 서명본 보관·외부 발행 기록                   | 외부 업체 계약과 서버 연동                |
| 앱 활동 이벤트·개발 API 서버               | 콘솔 Sentry 구성, 이벤트 집계 연결             | 전체·기관 수집 스위치, 별도 개발 API 환경 |

2026-11-19 앱 이벤트 지표 5개를 운영 콘솔에 배포했다. 상세 필드·표시 규칙·검증은 [앱 이벤트 연동 기록](app-events-20261119.md)을 따른다. 수집 시작 전의 미수집 표시는 API 미구현을 뜻하지 않는다.

크레딧은 백엔드 답변의 기존 실행 관문을 유지합니다. 부족 구간은 작업 전체를 한 쪽씩 직렬 처리하고, 잔여 1 이상이면 다음 쪽을 허용합니다. 결과 후 차감으로 마지막 쪽에서 음수가 될 수 있으며 이후 쪽은 막습니다. 원장은 기록·대사용입니다. 원자 예약 관문 전환을 미완료 항목으로 두지 않습니다.

발송 첨부는 파일당 10MB, 총 17MB, 최대 10개입니다. 답변 HTML의 총 20MB보다 정본 Notion의 최신 17MB 제한을 적용합니다. 업로드는 멱등 키를 지원하지 않으므로 결과 불명 시 재전송하지 않고 상세를 확인합니다.

운영 콘솔의 로그인 자격 증명은 제공되지 않았으므로 실제 MFA·재무 변경·메일 발송은 실행하지 않았습니다. Sentry 계정은 오류 수집 설정에만 사용했습니다. 로컬 자동 테스트와 예시 데이터 브라우저 검증은 인증된 실서버 통합 검증을 대체하지 않습니다.

## 배포

Node 22.12 이상. `npm ci`, `npm run check`. CI는 Node 24를 사용합니다.

- `npm run dev`: 로컬 예시 모드. 예시 로그인 `admin01` / `admin1234`.
- `npm run build`: `.env.production`의 HTTP API 연결로 `dist/` 생성.
- `npm run build:demo`: 명시적 예시 빌드. 운영 콘솔에 배포하지 않습니다.
- 개발 API: `.env.staging.example`을 `.env.staging.local`로 복사하고 실제 주소를 설정한 뒤 `npm run dev -- --mode staging` 또는 `npm run build -- --mode staging`.
- `.env.local` 및 CI 환경 변수가 모드별 설정보다 우선할 수 있으므로 배포 환경의 `VITE_API_SOURCE=http`을 확인합니다. `VITE_*` 값은 공개 번들에 포함됩니다. 비밀값을 넣지 않습니다.
- 정적 호스팅은 모든 앱 경로를 `index.html`로 fallback해야 합니다. 운영 콘솔 Origin, API CORS·WEB 운영자 권한·MFA 정책은 서버에서 설정합니다.
- 운영/개발은 서로 다른 콘솔 Origin과 API 주소를 사용합니다.
- `main`에 반영하면 기존 EC2 운영 서버로 자동 배포합니다. 배포 워크플로는 Node 24에서 의존성 설치, 타입 검사, 테스트, 운영 빌드, 보안 감사를 통과한 뒤 파일을 반영합니다. 인프라 생성과 DNS 변경은 포함하지 않습니다.

개발 도구 업데이트 참고: [Vite 마이그레이션](https://vite.dev/guide/migration), [Vitest 마이그레이션](https://vitest.dev/guide/migration/).
